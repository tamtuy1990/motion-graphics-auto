# Motion Graphics Auto

Deliver an enriched copy of an existing edit, an editable storyboard and a QA report. The job may include the finished base video plus a project bin of source footage, still images, logos and design assets. Read [project asset handling](references/project-assets.md) to inventory and select those assets. Source files stay immutable. Default visual edits preserve the base shot order and timing while adding graphics, image/video cutaways, picture-in-picture and restrained visual treatments; do not change the underlying edit or replace shots unless the user asks. Copy original audio streams without filters or replacement; added footage is silent by default. External narration is timing evidence, not an automatic replacement soundtrack.

## Execute

0. Before choosing/installing/upgrading Remotion, HyperFrames, or a renderer plugin, follow [live version policy](references/live-version-policy.md). On the first renderer-related invocation each Asia/Ho_Chi_Minh calendar day, call the DSH tool `motion_graphics_auto_check_releases`; it checks both GitHub latest-release endpoints and persists one shared result under `DSH_HOME`. Reuse that result for the rest of the day. Do not browse the same two endpoints again that day or treat this package's dated snapshot as current after its check date. Read [DeepSeek Harness integration](references/deepseek-harness-integration.md) when working on DSH request budgeting or plugin behavior.
1. Read [architecture](references/architecture.md), [project asset handling](references/project-assets.md), and [visual toolkit research](references/visual-toolkit-research.md) when choosing renderer capabilities. Probe the base video and inventory all supplied project media; fingerprint files and build an asset catalog with thumbnails/contact sheets. Establish speech track and audio offset before alignment. Use defaults only for ordinary SDR/CFR inputs; investigate VFR, HDR, nonzero timestamps or rotated sources.
2. Read [timing](references/timing.md) when extracting timings. With a script, align the words actually spoken; with no script, STT then align. Keep the original script separate from normalized aligner text. Do not fabricate missing timings. Record confidence and unaligned spans; skip uncertain graphic triggers or request a targeted correction if essential.
3. Keep every script sentence in order in `sentences.json`, including sentences that get no edit. Read [schema guide](references/schemas.md), [visual thinking guide](references/visual-thinking.md), and the [worked example](references/example-walkthrough.md). Infer what each passage is doing, then choose a fitting visual: a supplied asset, cutaway, picture-in-picture, graphic, card, effect, composed illustration, or no edit. Match selected project media by `asset_id` from the catalog; never invent filenames or source media. Catalog is a starting repertoire, not a closed menu. Numbers must come from verified speech, supplied data or an explicitly cited source. No chart from invented series.
4. Choose a sparse storyboard from sentence-level evidence. Default one active graphic, a minimum three-second gap between graphics, 2–6 second cards and no more than six events per minute; adjust for the content. Inspect representative frames around proposed events for faces, existing captions and key content. Encode protected areas. If placement is uncertain, omit or flag the event rather than obscure the speaker.
5. Validate schema and semantic constraints using `scripts/validate_job.py`. Choose one primary composition engine for a job: current starter targets Remotion; HyperFrames is a documented alternative, not an implemented adapter. Install mutually compatible exact versions only after live research and commit the lockfile. See [rendering](references/rendering.md) and [template catalog](references/template-catalog.md). Planner returns a structured visual spec, never arbitrary JSX. Render supported graphics and treatments; place supplied footage/images at the referenced frame windows. Keep added clips silent and explicitly map source audio streams.
6. Read [QA](references/qa.md). Check entry/peak/exit frames, alpha, text, evidence, timing and stream invariants. Local repairs may attempt twice; model-assisted repairs must share the job's single optional follow-up. Omit failed optional events with a report. Do not publish failed mandatory QA as a completed video. Return output video, storyboard, sentence manifest and QA report with stated omissions.

## Optional research assets

The user's separately enabled script-to-media workflow is described in [media research](references/media-research.md). It associates multiple ordered assets with each sentence. It does not authorize replacing shots in an overlay-only job. YouTube/search results are candidates, not downloadable/licensed production assets. Do not fetch external media unless this mode was requested and the source permits acquisition.

## Economy and reproducibility

Read [request budget](references/token-budget.md) before planning. Send the entire script as compact timed sentences in one planning request by default; do not split into time-based chunks. Allow at most one optional follow-up for the whole job, with a hard cap of five dispatch attempts including retries/fallback batches. Verify actual endpoint input/output limits; near-one-million-token context is a configured capability, not an output guarantee. Enforce caps in a persistent gateway when implementing the runtime; a prompt alone does not enforce them. Perform probe, sentence indexing, timestamp conversion, layout, rendering and technical QA with code. Reuse registered primitives and patch failed event IDs. Pin fonts, dependencies, model revisions, locale, colors and frame math. No random, wall-clock, network or CSS-time animations in rendering. Record tools and hashes in the job manifest.

## Package scope

This package includes schemas, validators, a probe helper, compositor and starter templates. It is not a installed one-click production service: STT/alignment adapters, orchestration, automatic subject detection, media retrieval and full visual QA are implementation milestones in [implementation plan](references/implementation-plan.md). Inspect available executables and adapters before promising a complete render. Do not claim a stage ran without its artifacts and logs.
